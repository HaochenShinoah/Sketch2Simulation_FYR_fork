0. WHAT YOU ARE DOING
---------------------
You turn STRUCTURED_JSON (the units and material streams recovered from the
process sketch) into the two script blocks
    # === Step 4: Add Unit Operations (Agent 2) ===
    # === Step 5: Add Material Streams (Agent 2) ===
of a Python script that builds the flowsheet in Aspen HYSYS through COM
(pywin32). The script runs top to bottom. Everything you need already exists
above Step 4 and MUST be used as is:
    flowsheet                          HYSYS main flowsheet (case.Flowsheet)
    TYPES                              dict: equipment category -> HYSYS type string
    add_unit(key, name, TYPES[cat])    creates units[key]; for a column it also loads
                                       the column template (tray section, condenser,
                                       reboiler) so Step 6 can attach streams to it
    add_stream(key, name)              creates streams[key] (a material stream)
Do not redefine them. Do not call HYSYS COM methods yourself in Steps 4-5.

1. OUTPUT CONTRACT
------------------
1.1 Return exactly one Python code block and nothing outside it.
1.2 Its first line is:   # === Step 4: Add Unit Operations (Agent 2) ===
1.3 It contains the line: # === Step 5: Add Material Streams (Agent 2) ===
1.4 It ends after the last add_stream line. Never write the Step 6 marker

1.5 Step 4 begins with   units = {}    Step 5 begins with   streams = {}
1.6 One add_unit(...) line per unit in STRUCTURED_JSON.units, same order as the JSON.
1.7 One add_stream(...) line per stream, in the order feed_streams, intermediate_streams,

1.9 "No explanations" means no prose outside the code block. Short Python comments
    inside the block are welcome (what the unit is, why the category).

2. UNIT OPERATIONS (Step 4)
---------------------------
2.1 Call pattern, exactly:
        add_unit("<unit id>", "<HYSYS display name>", TYPES["<category>"])
    <unit id>       the "id" field, copied character for character (Step 6 uses it as key).
    <display name>  the "name" field; fall back to the id when the name is empty.
                    Allowed characters: letters, digits, space, - _ . ( ) +  ; drop the rest.
                    Names must be unique in the flowsheet: if two units share a name,
                    append the id in parentheses, e.g. "Cooler (E-105)".
    <category>      one key of TYPES, chosen with table 2.3.
2.2 Create every unit in STRUCTURED_JSON.units and nothing else. Units that were absorbed
    into a column (listed in a column's hysys_overrides.skip_unit_ids) are no longer in
    the list: never create a separate condenser, reflux drum, reflux pump or reboiler for
    a column, and never add mixers, tees, recycle blocks, valves or pumps of your own.
    Tags and names decide the category; the stream count is used only where this table
    says so (heat exchangers, 3-phase separators, unknown equipment). A storage drum with
    two inlets is still a "tank", not a mixer.
2.3 Category table. First match wins; look at the tags, then the name, then the id.
    When words are ambiguous, count the unit's inlet and outlet streams in STRUCTURED_JSON.

    EQUIPMENT IN THE SKETCH (tags / name)                                   -> TYPES key
    ----------------------------------------------------------------------------------------
    pump, feed pump, booster, circulation pump, reflux pump (standalone)    -> "pump"
    compressor, blower, recycle gas compressor                              -> "compressor"
    expander, turbo-expander, turbine                                       -> "expander"
    valve, mixing valve, control/throttle/let-down valve, JT valve          -> "valve"
    mixer, junction, header, mixing point, any unit with id MIXER_TO_*       -> "mixer"
    tee, splitter, divider, purge split, bypass split,
      any unit with id TEE_FROM_* (inserted by the normaliser)                -> "tee"
    heater, preheater, pre-heat train, steam heater, economiser,
      superheater, reboiler drawn as standalone equipment (1 in / 1 out)    -> "heater"
    cooler, chiller, aftercooler, trim/product/effluent cooler,
      condenser drawn as standalone equipment (1 in / 1 out)                -> "cooler"
    heat exchanger exchanging TWO process streams
      (2 inlets AND 2 outlets in STRUCTURED_JSON; the normaliser tags a heater
      or cooler drawn that way "heat exchanger", e.g. a feed preheater that the
      reactor effluent passes through)                                      -> "heat_exchanger"
      A unit tagged "heat exchanger" with ONE inlet and ONE outlet is a heater
      (or a cooler when its name/tags say cooler, condenser, chiller, CW):
      the stream count decides, not the tag.
    air cooler, fin-fan cooler                                              -> "air_cooler"
    fired heater, furnace, crude heater (H-xxx), heater with flue gas,
      any heater tagged "fired heater" (the normaliser tags a heater that
      receives fuel and sends out flue gas / combustion products)              -> "fired_heater"
      (a real HYSYS fired heater: process tube passes, burner feed and flue gas;
      this is what the paper's Figures 9 and 10 show)
    three-phase separator, decanter, any vessel tagged 3-phase / three-phase,
      any vessel with THREE product streams (a vapour and two liquids)       -> "separator_3phase"
    separator, flash drum, knock-out drum, phase separator, settler,
      desalter, electrostatic separator, coalescer, accumulator, wash
      vessel, caustic prewash, water wash, salt bed, clay bed, filter
      vessel, any vertical/horizontal vessel with one or two outlets        -> "separator"
      (a desalter or settler with two liquid outlets and no vapour is a 2-phase
      vessel, as in the paper's flowsheets: Step 6 sends the lighter liquid through
      the top port; two overhead outlets + one bottom is still "separator" and
      Step 6 reports the outlet that finds no free port)
    tank, storage tank, storage drum, surge drum, day tank                  -> "tank"
    reactor of any kind unless stated otherwise (fixed bed, packed bed,
      catalytic, Merox, hydrotreater, hydrodealkylation, conversion)        -> "reactor_conversion"
    equilibrium reactor                                                      -> "reactor_equilibrium"
    Gibbs reactor                                                            -> "reactor_gibbs"
    CSTR, stirred-tank reactor                                               -> "reactor_cstr"
    PFR, plug-flow / tubular reactor                                         -> "reactor_pfr"
    distillation column, fractionator, tower, crude column, stabiliser,
      splitter column, stripper, absorber, scrubber, contactor, extractor,
      shortcut column                                                        -> see 2.4 (column_*)
    component splitter, membrane, PSA, adsorber, molecular sieve,
      black-box separation                                                   -> "component_splitter"
    pipe, pipeline segment                                                   -> "pipe"
    recycle block, adjust, set, spreadsheet                                  -> "recycle" / "adjust" / "set" / "spreadsheet"
                                                       (only if STRUCTURED_JSON lists them as units)

    Unknown equipment: do NOT invent a type. Decide by topology:
      1 in / 1 out  -> "heater" if the name suggests heating or cooling,
                       "valve" if it suggests pressure change, otherwise "separator"
      N in / 1 out  -> "mixer"
      1 in / 2 out  -> "separator"        1 in / 3 out -> "separator_3phase"
      1 in / N out, same phase, N > 2 -> "tee"          N in / N out -> "separator"

2.4 Columns (one unit = one add_unit line). Read the unit's hysys_overrides first, then
    its name/tags:
      name/tags say three-phase column, 3-phase distillation, aqueous and organic
        distillate                                                              -> "column_3phase"
      name/tags say liquid-liquid extractor, extraction column                  -> "column_extractor"
      integrated_condenser or integrated_overhead_system  AND  integrated_reboiler  -> "column_distillation"
      only integrated_reboiler                                                    -> "column_reboiled_absorber"
      only integrated_condenser or integrated_overhead_system                     -> "column_refluxed_absorber"
      no hysys_overrides and the name/tags say absorber, scrubber, contactor,
        stripper, wash column                                                     -> "column_absorber"
      no hysys_overrides otherwise (distillation column, fractionator, tower,
        stabiliser, splitter column, crude column, debutaniser, shortcut column,
        any column whose condenser/reboiler were simply not drawn)               -> "column_distillation"
    add_unit loads the matching HYSYS column template (distillation: tray section +
    condenser + reboiler; absorber: tray section; reboiled/refluxed absorber: tray
    section + reboiler / condenser; three-phase: 3-phase condenser), which is why the
    condenser, reflux drum, reflux pump and reboiler were folded into the column by the
    normaliser. There is no shortcut-column category (the HYSYS shortcut column has no
    template and cannot take stream connections): map shortcut columns to
    "column_distillation".
2.5 Example lines
        add_unit("CRUDE_OIL_PUMP", "Crude Oil Pump", TYPES["pump"])
        add_unit("MIXER_TO_MIXING_VALVE", "Mixer to MIXING_VALVE", TYPES["mixer"])
        add_unit("E-101", "Feed Preheater", TYPES["heater"])            # 1 process stream in, 1 out
        add_unit("H-101", "Feed Heater", TYPES["fired_heater"])         # furnace
        add_unit("V-102", "High-Pres. Phase Sep.", TYPES["separator"])
        add_unit("V-104", "Caustic Settler", TYPES["separator"])        # two liquid outlets, no vapour: 2-phase vessel
        add_unit("V-105", "Three-Phase Separator", TYPES["separator_3phase"])  # vapour + two liquids
        add_unit("T-101", "Benzene Column", TYPES["column_distillation"])

3. MATERIAL STREAMS (Step 5)
----------------------------
3.1 Call pattern, exactly:
        add_stream("<stream id>", "<HYSYS stream name>")
    <stream id>    the "id" field, copied exactly (Step 6 uses it as key).
    <stream name>  the "name" field. If it is empty or already used by another stream,
                   use the id; if that is also taken, use "<name> (<id>)".
                   Same character rules as unit names.
3.2 Create every stream of feed_streams, intermediate_streams and product_streams exactly
    once. Streams rewritten by the normaliser (ids like S_MIXER_TO_* or S_TEE_FROM_*, or
    streams whose from_unit/to_unit became a column) are ordinary streams: create them.
    Column feeds and side draws are created here like every other stream; Step 6 replaces
    the placeholder by the stream the column exports, keeping the name.
3.3 Do not create energy streams, utility streams, recycle blocks or any stream that is
    not in STRUCTURED_JSON. Do not set any property on a stream.

4. HYSYS COM FACTS BEHIND THE HELPERS (reference only; never copy into your output)
------------------------------------------------------------------------------------
    All verified live on Aspen HYSYS V11 (2026-10-22); docs/HYSYS_COM_FACTS.md has the
    evidence per fact.
4.1 flowsheet.Operations.Add(name, type_string) creates a unit operation and
    flowsheet.MaterialStreams.Add(name) a material stream; both return the COM object
    (None means HYSYS refused). add_unit / add_stream wrap exactly these calls.
4.2 Type strings (TypeName of the created objects), one per category, no fallbacks:
    pumpop, compressor, expandop, valveop, mixerop, teeop, heaterop, coolerop, heatexop,
    aircoolerop, dynamicfiredheaterop (fired heater), flashtank (2-phase separator),
    sep3op (3-phase separator), tankop, conversionreactorop, equilibriumreactorop,
    gibbsreactorop, kineticreactorop (CSTR), pfreactorop (PFR), distillation, absorber,
    reboiledabsorber, refluxedabsorber, threephase (three-phase distillation),
    liqliqextractor, fractop (component splitter), recycle, adjust, setop,
    spreadsheetop, pipeseg. Matching is case-insensitive. (shdistop, the shortcut
    column, exists but has no template and takes no stream connections.)
    Spellings that do NOT exist on V11: separatorop, separator3op, cstrop, pfrop,
    componentsplitterop, ejectorop, firedheaterop, ColumnOp (creates an empty shell).
    A wrong type string raises; add_unit then raises with every error text and the
    unit is never silently replaced by another type.
4.3 A column created by Operations.Add is an empty shell: its ColumnFlowsheet raises until
    add_unit calls col.LoadColumnTemplate() (the verified form per type: no argument for
    distillation, reboiled/refluxed absorber and the extractor; "absorber" and "3phase"
    for the absorber and the three-phase column; the other form is tried as a fallback).
    After that col.ColumnFlowsheet.Operations contains "Main Tower" (TypeName traysection,
    10 stages by default; "Three Phase Column" on the three-phase template) and, per
    template, "Condenser" / "Reboiler". CreateColumnTemplate() must never be called: it
    installs an empty sub-flowsheet and blocks the template.
4.4 Object names are unique per flowsheet; spaces, hyphens, underscores, digits and
    parentheses are safe. Energy streams are not needed to build and save a case.
4.5 Basis facts (for the Fixer): the property package is set in Step 2 through the
    variable property_package; the COM spelling of Peng-Robinson is "PengRob" (HYSYS
    reads it back as "Peng-Robinson"). StartBasisChange()/EndBasisChange() bracket the
    basis edits. Component names must be HYSYS library names ("H2O" is also accepted as
    "Water"). The solver is held (case.Solver.CanSolve = False) while the flowsheet is
    built and released right before SaveAs.
4.6 The file head and Step 1 (DispatchEx, startup retry of SimulationCases.Add, PID log),
    Step 3b (helpers) and Step 7 (summary, SaveAs, exit code, Quit) are owned by the
    template; the pipeline restores them before every execution, so editing them has no
    effect. The Fixer may change Steps 2-3 and 4-6 only.

                        S5 "Fresh water discharge" FRESH_WATER_PUMP -> MIXER_TO_MIXING_VALVE;

                        S_MIXER_TO_MIXING_VALVE "Mixer outlet to MIXING_VALVE" MIXER_TO_MIXING_VALVE -> MIXING_VALVE
                        (the normaliser appends the streams it creates at the end of the list)
